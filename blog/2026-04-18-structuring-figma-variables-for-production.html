Structuring Figma variables for production

How to organize collections, configure token scoping, and set up private publishing conventions that prevent mistakes in Figma and bridge cleanly to code.

Figma Variables are the most powerful capability added to design systems since Autolayout. But without architectural discipline, teams quickly recreate the exact same chaos they had with legacy color styles: a single cluttered collection with 900 variables, broken mode switching, and designers picking accent oranges for text fills.

To run a design system that twenty designers can use without guardrails constantly failing, you need to structure your Figma Variables like software engineers structure data: isolated collections, strict type scoping, and hidden private layers.

1. The 3-Collection architecture

Never place raw palette colors and functional semantic tokens inside the same Figma collection. Figma resolves modes at the collection level, so bundling them forces raw hexes into mode switching where they don't belong.

Instead, establish three distinct collections in your library file:

  • Collection 1: Primitives (Single Mode): Contains immutable raw hex values and spacing numbers (e.g. blue/500: #0066FF, space/16: 16). Has only one default mode. These are purely dictionary words.
  • Collection 2: Semantic (Multi-Mode): Contains functional role tokens (e.g. surface/canvas, text/default, action/primary/bg). Has modes configured for Light and Dark (or Brand A, Brand B). Every variable here is an alias pointing back to Collection 1.
  • Collection 3: Component (Overrides): Reserved for specific sub-elements with unique exceptions (e.g. slider/track/fill). Keeps component-specific quirks from polluting the universal semantic namespace.

When an engineer toggles a screen from Light to Dark, Figma only flips the modes in Collection 2. Primitives remain undisturbed, eliminating circular dependency bugs.

2. Variable Scoping: the invisible guardrails

The fastest way a design system degrades is when designers accidentally apply tokens to the wrong CSS properties — using a background surface token on body text, or a border-width token on corner radius.

Figma provides Variable Scoping to prevent this at the tool level. In your variable edit modal, explicitly limit each variable to its intended properties:

  • Surface & Background tokens: Scope to Frame fill and Shape fill only. Turn off Stroke and Text fill.
  • Text tokens: Scope exclusively to Text fill. When a designer opens the text color picker, they will only see text-appropriate tokens.
  • Border tokens: Scope strictly to Stroke.
  • Radius tokens: Scope to Corner radius. Turn off width, height, and gap.

Scoping reduces the visual noise in your team's color and number pickers by 75%. Designers can't make mistakes because invalid tokens literally do not appear in the menu.

3. The private token convention

Designers building application screens should never interact with raw primitives like blue/500 or gray/100. If they use raw primitives, dark mode breaks because those tokens have no mode awareness.

To prevent raw primitives from appearing in consumer files, use Figma's private publishing convention:

  1. Prefix internal collections or variable groups with an underscore (_primitives/blue/500) or dot (.primitives/blue/500).
  2. Or uncheck the "Hide from publishing" toggle in the variable collection settings.

When you publish your library, your semantic variables (`action/primary/bg`) remain fully accessible to product designers, while the underlying primitive aliases stay private inside the library file. The abstraction holds.

4. The Figma-to-Code contract

Figma Variables should never be a manual island. Because Figma exposes variables through its REST API, your variables collection can function as the true design token source of truth:

Figma Variables (Collection 1 & 2)
       ↓ (Figma REST API / Token Studio)
design-tokens.tokens.json (W3C standard format)
       ↓ (Style Dictionary Build Engine)
dist/tokens.css  |  dist/tokens.ts  |  dist/tokens.swift

When a design systems designer adjusts a token alias in Figma, a GitHub Action triggers the API export, runs automated contrast verification tests, and commits the updated CSS variables directly into the engineering repository. No spreadsheets, no Slack messages, and zero manual hex translation.
